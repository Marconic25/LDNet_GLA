# LDNet Reduced-Input Redesign: 2-Input Aeroelastic ROM

**Date:** 2026-05-22  
**Author:** Marco Niccolini  
**Status:** Design approved

---

## Context

The current LDNet model takes 6 input signals `[h, ḣ, α, α̇, δ, W_gust]` and outputs `[C_L, C_M]`. It acts as a pure aerodynamic surrogate: the structural states are fed in from outside.

The key insight is that if the training dataset is generated by varying only `δ(t)` and `W(t)` — with the structural states `h(t)`, `α(t)` computed internally by the structural ODE from fixed equilibrium initial conditions — then a PCA of the dataset would reveal that the effective dimensionality is 2, not 4+. The structural states are not independent variables; they are deterministic outputs of the structural dynamics driven by `δ` and `W`.

Furthermore, in the deployment scenario (gust load alleviation), the controller always acts on a system starting from the same aerodynamic trim condition. This means that `h` and `α` carry no additional information beyond what `δ(t)` and `W(t)` already encode.

The proposed redesign reduces LDNet to 2 input signals `[δ, W]`, making it a **full aeroelastic ROM**: the latent state `z` must capture both the aerodynamic memory and the implicit structural dynamics. The architecture shown in the design note separates LDNet (learning `δ, W → C_L, C_M`) from the explicit structural ODE (computing `C_L, C_M → h, α`), closing the loop externally.

## Architecture

### Current (6-input) vs Proposed (2-input)

```
CURRENT:
  [h, ḣ, α, α̇, δ, W] ──► LDNet ──► [C_L, C_M]
  (structural states fed from outside)

PROPOSED (matches design sketch):
  [δ, W] ──► LDNet ──► [C_L, C_M]
                              │
                    Structural ODE (physical)
                    ms² + Rs + k_h  →  h
                    Is² + Rs + k_α  →  α
                              │
                    Controller ◄──── [h, α]
                              │
                              └──► δ (fed back to LDNet)
```

The loop is closed externally: LDNet is stateless except for `z`, which is propagated forward in time.

### LDNet Internal Structure (unchanged)

```
z(t) ──┐
δ(t) ──┤── NNdyn(z, δ, W) ──► dz/dt ──► z(t+dt)  [Euler integration]
W(t) ──┘

z(t) ──┐
δ(t) ──┤── NNrec(z, δ, W, x_space) ──► [C_L, C_M]
W(t) ──┘
```

- `NNdyn`: Dense(n_lat, tanh) × 2 → Dense(n_lat)
- `NNrec`: Dense(24, tanh) × 4 → Dense(2)
- Euler integration: `z(t+dt) = z(t) + dt_norm * NNdyn(z, δ, W)`
- `dt_norm = dt / time_constant` (normalized time step, same as current)

## Dataset Generation

### Simulation Strategy

**Tool**: full co-simulation on the cluster via `cosim_driver.py` (OpenFOAM pimpleFoam + structural Python integrator). This code is not present in this repository — it runs on the HPC cluster and produces CSV output files which are then transferred here for training.

Generate a new GLA dataset varying only `δ(t)` and `W(t)`:

1. **Gust profiles**: vary `W_peak ∈ {10, 20, 30, 40, 50, 60} m/s` and gust duration `T_g ∈ {0.5, 0.8, 1.0, 1.5} s` (1-cosine EASA CS-25 profile)
2. **Flap schedules**: implement a "sensible" control law covering a wide range of `δ(t)` trajectories:
   - **Scheduled ramps**: `δ` ramps to ±5°, ±10°, ±15°, ±20° at different rates
   - **Feed-forward law** (via `cosim_driver.py --law 5`): `δ(t) = -K_eff * W_gust(t - τ)` with `K_eff ∈ {0.1, 0.3, 0.5} deg/(m/s)`, `τ ∈ {0, 0.05, 0.1} s`
   - **No-control baseline**: `δ = 0` for all gust cases
3. **Fixed initial conditions**: always start from aerodynamic trim equilibrium `(h_eq, α_eq)` computed by `compute_static_equilibrium()` in `cosim_driver.py`
4. **Output**: each simulation produces a CSV with columns `[t, h, ḣ, α, α̇, δ, W_gust, C_L, C_M, Fy, Mz]`, transferred to `data/` for training

The `cosim_driver.py` already supports all the required flap laws (`--law 0` for tabulated, `--law 5` for feed-forward). No changes to the co-simulation code are needed for dataset generation.

### PCA Validation (before retraining)

Before retraining, run PCA on the generated dataset to confirm the dimensionality hypothesis:

1. Stack all `[h, ḣ, α, α̇, δ, W]` columns across all simulations into a matrix `X ∈ ℝ^{N×6}`
2. Standardize (zero mean, unit variance per column)
3. Compute eigenvalues of the covariance matrix
4. Plot cumulative explained variance vs number of components
5. **Expected result**: ~99% of variance explained by 2 components (corresponding to `δ` and `W` directions)

If the PCA confirms dimensionality ≤ 3, proceed with the 2-input retraining.

## Training Changes

### Input Signal Reduction

Modify `TestCase_OF.py` and `data/preprocess_GLA.py`:

- **Before**: `input_signals = [h, hd, a, ad, delta, W_gust]` (6 signals)
- **After**: `input_signals = [delta, W_gust]` (2 signals)

`h`, `hd`, `α`, `αd` are removed from LDNet inputs entirely. They remain in the CSV/HDF5 as reference columns for validation, but are not fed to the network.

### Normalization Bounds

Update `config.json` normalization:
```json
"input_signals": {
  "delta":  {"min": -20.0, "max": 20.0},
  "W_gust": {"min": 0.0,   "max": 70.0}
}
```

### Latent State Sensitivity Analysis

Train separate models for `num_latent_states ∈ {3, 5, 8, 10, 15}` and evaluate:
- NRMSE on test set for `C_L` and `C_M`
- Pearson correlation coefficient
- Training convergence (Adam + BFGS phases)

Select the minimum `num_latent_states` that achieves NRMSE < 5% on both outputs.

### Training Configuration

All other hyperparameters remain unchanged:
- `dt_train = 0.2 s` (resampled from CFD `dt = 0.002 s`)
- `time_constant = 5.4 s`
- Adam: 200 epochs, lr=1e-2
- BFGS: 10,000 epochs
- Loss: MSE(velocity) + `weight_direction` × MSE(direction) on `[C_L, C_M]`

## Model Integration in Closed-Loop System

### Modified `src/aerodynamics/model.py`

The `step_tf` function (used by MPC's GradientTape) must be updated:

```python
# Before:
def step_tf(self, z, x_struct, delta, W):
    inputs = tf.concat([z, x_struct, delta, W], axis=-1)  # 1+4+1+1 = 7

# After:
def step_tf(self, z, delta, W):
    inputs = tf.concat([z, delta, W], axis=-1)  # n_lat + 1 + 1
```

The structural state `x_struct = [h, ḣ, α, α̇]` is removed from the LDNet forward pass entirely.

### Modified Closed-Loop Simulation (`src/aeroelastic/system.py`)

The closed-loop simulation must now integrate the structural ODE explicitly at each step:

```
for each timestep t:
  1. C_L, C_M = LDNet(z, δ(t), W(t))       # aerodynamic forces
  2. Fy = C_L * q_inf,  Mz = C_M * q_inf   # dimensional forces
  3. [h, ḣ, α, α̇] = structural_ODE.step(Fy, Mz)  # structural integration
  4. δ(t+dt) = controller([h, α], reference)       # control law
  5. z(t+dt) = z(t) + dt_norm * NNdyn(z, δ, W)    # latent update
```

This mirrors the `cosim_driver.py` structure exactly — LDNet replaces pimpleFoam.

### Initial Latent State

Since the system starts from a fixed trim condition, `z₀` must be calibrated to the trim state. Options:
1. **Zero initialization**: `z₀ = 0` (simplest, may require a "burn-in" period)
2. **Trim calibration**: run LDNet forward for `t_burnin` with `δ=0`, `W=0` starting from `z₀=0` until `C_L ≈ C_L_trim` — use the converged `z` as the starting state

Recommended: option 2 with `t_burnin = 0.5 s` (≈ 2.5 oscillation periods).

## Verification Plan

1. **PCA validation script** (`src/pca_validation.py`): run PCA, plot explained variance, confirm dimensionality ≤ 3
2. **Sensitivity analysis**: train 5 models with different `num_latent_states`, compare NRMSE table
3. **Open-loop validation**: drive LDNet-2input with recorded `[δ(t), W(t)]` from a held-out CFD simulation and compare predicted `C_L(t)`, `C_M(t)` vs CFD
4. **Closed-loop validation**: run full aeroelastic loop (LDNet-2input + structural ODE) and compare `h(t)`, `α(t)`, `C_L(t)`, `C_M(t)` against the full co-simulation (OpenFOAM reference)
5. **MPC integration test**: plug the new LDNet into the existing MPC controller (`src/control/mpc.py`) and verify GLA performance metrics are preserved or improved vs the 6-input baseline

## Risks and Mitigations

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| z cannot capture structural dynamics with 5 states | Medium | Sensitivity analysis — increase to 8–15 if needed |
| Burn-in period introduces transient error in MPC | Low | Use trim calibration for z₀ (option 2 above) |
| PCA does not confirm 2D dimensionality (h, α partially independent) | Low | The fixed CI assumption is confirmed — if PCA shows 3D, the 3rd component likely corresponds to the transient decay and can still be ignored at training time |
| Training dataset insufficient coverage of δ × W space | Medium | Ensure feed-forward law generates diverse `δ(t)` trajectories; augment with random ramp schedules |
